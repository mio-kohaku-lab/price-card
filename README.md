# カードノート Ver.0.2.9

Android Chrome向けのプライスカード商品管理PWAです。カメラ・画像から読み取り、確認修正後に端末内へ保存し、JANバーコードを大きく表示できます。

商品情報と画像は外部へ送信しません。商品情報は各端末のIndexedDBに保存し、JSONでバックアップできます。画像は保存しません。公開リポジトリには商品データや実物のテスト写真を含みません。

## Androidで使う

1. 公開されたGitHub PagesのURLをChromeで開く。
2. 初回はWi-Fi等でアプリ・OCR辞書の読込を待つ（約33MB）。
3. Chrome右上の「⋮」→「ホーム画面に追加」→「インストール」。表示名はChromeのバージョンにより異なります。
4. ホーム画面の「カードノート」を開き、カメラの利用を許可する。
5. 起動するとカメラが開きます。カード全体をガイド枠いっぱいに合わせ、少し静止してください。
6. 自動で読み取った商品名・JANがフォームに入ります。必要な箇所だけ直し、「保存して次へ」で次のカメラへ戻ります。確認チェックや保存確認ダイアログはありません。

## 連続スキャン

- 自動撮影は約180ms間隔の4フレームで静止を確認します。白地に文字・バーらしい模様があることを条件にしています。これはカード内容を保証する判定ではありません。
- 反応しないときは「今すぐ読み取る」で撮影からOCRまで進みます。カメラ撮影後の範囲指定は不要です。
- 保存後は次のカメラへ自動で戻ります。同じカードの連続撮影は抑止します。次のカードで反応しない場合は一度枠から外すか、手動ボタンを押してください。
- 登録済みJANはフォーム内と保存ボタンに「更新」と表示します。保存を押すと同じ商品を更新し、件数は増えません。以前の価格などは保持します。
- OCRエンジンは連続読取中に再利用します。初回の準備時間と、各画像のOCR処理時間は必要です。
- 読み取り直し、画像の範囲調整・四隅補正は必要な場合だけ使用できます。画像ファイルからの読み取りでは1枚を範囲指定します。
- カメラ許可は初回に必要です。権限拒否や自動起動が制限された環境では、再開ボタン・画像選択・手入力が使えます。
- 画面を離れるとカメラは停止します。戻った際は「カメラを再開」で再開できます。
- 商品一覧から既存商品を編集した場合は、保存後に商品詳細へ戻ります。

## 制約

- OCRには誤読があります。商品名とJANコードの確認・手入力補完が必要です。価格・DEPT・販売許容数値は読み取り対象外です。既存の値は編集・同JANの再登録でも保持され、JSONでも引き継げます。
- 元カードの形式をデコードできない場合、JANのみの仮EANバーコードを生成します。実店舗のスキャナで互換性を検証してください。
- Android実機と店舗スキャナでの動作は利用者の環境で確認してください。
- ブラウザのデータ消去や機種変更に備え、定期的にJSONを書き出してください。
- 店舗の公式アプリではありません。

## ローカル開発

Node.js 20以上で実行します。

```sh
node scripts/setup.mjs
node --test tests/*.test.mjs
node scripts/serve.mjs
```

`http://localhost:5173` を開きます。setupはバージョン固定の公開ライブラリ・辞書を取得します。GitHub Actionsでも同じ処理で取得し、配信時は同一サイト内に同梱します。

## 公開

GitHub Settings → Pages → Source をGitHub Actionsに設定します。mainへのpushでテストと公開を実行します。PWA更新時はsw.jsのCACHE名を更新してください。

ライセンス情報: [THIRD-PARTY.md](THIRD-PARTY.md)。依存ファイルのライセンス文書はsetup時にvendorへ取得します。

## インストールと更新の案内

画面上部の「インストール・更新」に、Chromeからbeforeinstallpromptを受け取った場合だけインストールボタンを表示します。イベントがないことをインストール済みとは判定せず、過去のインストールをlocalStorageにも記録しません。standaloneは現在の起動方法の確認にのみ使います。Chrome自身の誤ったインストール済み判定はアプリから変更できません。

古い画面のままの場合は `refresh.html` を開いて最新版を準備します。Service Workerのバージョン応答を確認してからアプリへのリンクを表示します。IndexedDB・商品データ・他のサイトの登録には触れません。入力中の自動再読み込みはしません。更新してもAndroidのインストール問題が解決するとは限りません。実機でボタンの表示、キャンセル、ホーム画面起動を確認してください。

## 一覧表示と日付（Ver.0.2.2）

ヘッダーは32px、インストール・更新は本文の後に配置。商品一覧は行間にマージンを置かないテーブルで商品名・JAN・日付を表示し、商品名を押すと詳細を開きます。カメラ撮影時のcapturedAt、画像読込時のreadAtを保存し、端末の時刻帯でYYYY/MM/DD表示。過去商品・手入力はcreatedAtを「登録」と明記し、不明なら「日付不明」。画像ファイルのEXIF撮影日は取得しません。再撮影は新しい撮影日に更新、通常の編集では保持。JSONバックアップの日時も復元します。

## 一覧の管理操作（Ver.0.2.3）

商品名は横幅全体を使う1行、その下に左JAN・右登録日、続けて基材数と〇✕を表示します。長い商品名は横にスワイプして全文を確認できます。日付はcreatedAt（登録日）で、撮影日・読込日は引き続きデータに保持します。

- 既存商品・新規商品は初期状態〇、基材は空欄。変更は端末内へ自動保存します。数値は入力確定（フォーカスを外すかキーボードの完了）で保存。整数0以上、8桁までです。
- ✕または基材0ならグレー背景。空欄は0と区別します。基材を空欄や正数に戻しても✕ならグレーのままです。
- 保存した商品の右端「並べ替え」で白→グレー、それぞれ登録日の新しい順。登録日不明はグループ末尾。検索中も全商品を並べ替えてから検索結果を表示します。
- 操作中に位置が変わらないよう状態・基材の変更だけでは並べ替えません。一覧を開き直した時は登録日順です。
- 同一JANの再スキャンでも〇✕と基材を保持。JSONの書き出し・読み込みにも含みます。保存失敗時は表示を保存済みの状態に戻し、エラーを行内に表示します。

## スリム表示・長押し削除（Ver.0.2.4）

商品欄は2行で表示。商品名の下にJAN、登録日、基材、〇✕を横並びにし、基材入力と〇✕は高さ24pxに縮小しています。小さな操作領域は利用者の省スペース指定によるものです。

商品名・JAN・日付などの商品欄を600ms長押しすると削除確認を開きます。確認で削除を選んだ場合だけ削除し、キャンセルでは保持。基材入力・ラベル・〇✕は長押し削除の対象外です。8pxを超える移動、スクロールに伴うpointercancel、指が欄から離れた場合は判定をキャンセル。長押し後に商品詳細が開くクリックも抑止します。詳細画面の削除ボタンは維持しています。Android実機でスクロール・長押しの動作確認が必要です。

## 自動撮影の反応（Ver.0.2.5）

撮影前の繰り返しバーコード解析を除き、最大96pxのプレビューを約180ms間隔で確認します。カード候補が4フレーム静止すると撮影（理論上約540ms＋端末の描画・処理時間）、その後に元の解像度でJANと商品名を解析。枠の緑色と案内文で静止検出・同一カード抑止・自動OFFを表示します。白地・印字の判定は枠の余白を多少許容するよう調整しています。

これは撮影開始を早める変更です。OCR完了までの時間や実機の精度は保証しません。次のカードが似ていて抑止される場合は一度枠から外すか手動撮影してください。誤検出した内容は保存前に修正できます。自動保存は行いません。

## 小さいカード・タッチ長押しの改善（Ver.0.2.6）

枠を幅84%から64%（上限280px）に縮小し、離してピントを合わせやすくしました。カードの白地条件が合わなくてもコントラストと模様を検知できれば7フレームの静止で撮影開始。通常カード候補は4フレームです。180ms間隔なので目安0.6〜1.1秒＋処理時間。露出の一様な変化は動きから除外し、累積移動は除外しません。文字以外の模様でも反応することがあり、認識結果は保存前に修正可能。自動保存はしません。

長押しはTouch Eventsも直接処理し450msで確認。Androidのpointercancel/leaveだけではタッチのタイマーを取り消さず、実際のtouchmove（12px超）・touchcancel等で中断します。静止中のcontextmenuも確認につなぎ、二重発火を抑止。入力や〇✕は対象外。Android実機での改善はまだ確認できていません。

## 5カウントと商品名OCR（Ver.0.2.7）

模様による静止判定は7から5フレーム（約720ms＋処理時間）に短縮。通常カード候補は4フレームを維持。カウントは撮影開始までの待ち時間で、撮影前にピントが間に合うかは端末次第です。

商品名は従来どおり上部40%を対象とし、撮影ガイドに対象領域を表示。2行に限定すると添付写真のプリンなど3行目の容量が欠けるため、2〜3行を含めています。商品名領域だけグレースケール・濃淡補正・白余白追加を行い、OCRは1回のまま。新しい画像補正の実写真での精度改善は未確認で、ボケた文字を復元するものではありません。

## 4カウント・カテゴリ（Ver.0.2.8）

静止判定を通常・模様とも4フレームに統一。カメラのチェック欄に4カウントと明示します。7と表示される場合は旧版なのでrefresh.html?v=028から更新してください。

一覧の検索を撤去し、全て・日配・飲料・ドライの絞り込みボタンを配置。その他と未選択は全てに表示します。既存の並べ替え（白→グレー、各登録日の新しい順）は残します。

編集と読取結果フォームに未選択・日配・飲料・ドライ・その他のタブ風ラジオボタンを追加。初期値は未選択で、保存時にカテゴリを記録します。既存商品の再撮影ではカテゴリを維持し、フォームで明示的に選び直した場合は変更を反映。JSONバックアップも対応。

## 一覧の操作部分をスリム化（Ver.0.2.9）

商品一覧見出し18px、読み取る・手入力・書き出す・読み込むボタン32px高、カテゴリと並べ替え28px高へ縮小。上下余白とバックアップ説明も詰めています。商品欄、カメラ・編集画面の操作サイズは変更していません。
